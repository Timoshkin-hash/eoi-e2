# Памятка по параметрам JSON задачи №2

Файл `data/task_02_social_network_config.json` содержит все исходные данные и управленческие допущения модели социальной сети «ГородСоцСеть».

Notebook загружает эти значения автоматически. После изменения JSON необходимо запустить все ячейки Notebook с начала: изменятся таблицы, графики, NPV и текстовые рекомендации.

## Основные параметры

| Параметр | Что означает | От чего зависит |
|---|---|---|
| `task_id` | Номер экзаменационной задачи. | Заголовок Notebook. |
| `title` | Название задачи. | Заголовок и постановка задачи. |
| `project_name` | Название проекта. | Текст постановки и заключение. |
| `market_potential_users` | Максимальный потенциал рынка, чел. | Ограничивает траекторию пользователей и участвует в расчёте ориентировочного прироста. |
| `initial_users` | Начальная база пользователей. | Начальная точка траектории роста и расчёт времени достижения критической массы. |
| `growth_before_critical` | Месячный рост до критической массы. | Траектория пользователей, критическая масса, NPV и срок достижения порога. |
| `growth_after_critical` | Месячный рост после критической массы. | Траектория после перехода через порог и сценарный NPV. |
| `network_value_coefficient_rub_per_user_squared` | Коэффициент `k` в формуле Мэткалфа. | Ценность сети: `V(N) = k × N²`. |
| `monthly_maintenance_cost_rub` | Ежемесячные затраты на поддержание сети. | Критическая масса, прибыль, NPV, минимальный ARPU и рекомендации. |
| `cac_rub` | Исходная стоимость привлечения пользователя. | Строгая критическая масса и строгий NPV. |
| `operational_cac_rub` | Операционный CAC для управленческого сценария. | Операционная критическая масса, основная траектория, NPV и маркетинговый бюджет. |
| `arpu_rub_per_user_month` | Средний доход от одного пользователя в месяц. | Выручка, прибыль, критическая масса, NPV и точка безубыточности. |
| `horizon_months` | Горизонт расчёта в месяцах. | Количество строк траектории, период NPV и сценарный анализ. |
| `annual_discount_rate` | Годовая ставка дисконтирования. | Справочный финансовый параметр. Основной помесячный расчёт использует `monthly_discount_rate`. |
| `monthly_discount_rate` | Ставка дисконтирования за месяц. | Дисконтирование прибыли и расчёт NPV. |

|---|---|---|

| `sensitivity_growth_search_max` | Верхняя граница поиска минимального темпа роста для NPV ≥ 0. | Диагностический порог роста. |

## Сценарии роста

Объект `scenarios` содержит независимые сценарии:

```json
"scenarios": {
  "Пессимистичный": {
    "growth_before": 0.02,
    "growth_after": 0.10
  },
  "Базовый": {
    "growth_before": 0.03,
    "growth_after": 0.15
  },
  "Оптимистичный": {
    "growth_before": 0.05,
    "growth_after": 0.20
  }
}
```

`growth_before` задаёт рост до критической массы, а `growth_after` — рост после неё. Notebook автоматически строит пользовательскую траекторию и NPV каждого сценария.

## Параметры стратегических рекомендаций

| Параметр | Что означает | Как используется |
|---|---|---|
| `market_launch_cost_reduction_rub` | Целевой уровень затрат при локальном запуске. В текущем сценарии — 200 000 руб./мес.; это управленческое допущение, а не автоматически достигнутый факт. | Отображается в ожидаемом эффекте стратегии локального запуска. |
| `partnership_arpu_target_rub` | Целевой ARPU при партнёрстве с местным бизнесом. | Отображается в ожидаемом эффекте партнёрской стратегии. |
| `engagement_improvement` | Целевое повышение вовлечённости от геймификации. | Формируется в таблице стратегий. |
| `conversion_improvement` | Целевое повышение конверсии от аналитики и A/B-тестов. | Формируется в таблице стратегий. |

## Ключевые формулы

### Критическая масса

```text
Nкрит = (затраты на поддержание + CAC × ориентировочное число новых пользователей) / ARPU
```

Ориентировочное число новых пользователей рассчитывается как:

```text
потенциал рынка × темп роста до критической массы
```

### Пользовательская траектория

```text
N(t) = N(t − 1) × (1 + темп роста)
```

После достижения критической массы используется `growth_after`. Траектория не может превышать `market_potential_users`.

### Прибыль за месяц

```text
Прибыль = ARPU × пользователи − поддержание − CAC × новые пользователи
```

Начальная база месяца 0 не считается новыми пользователями, поэтому CAC в месяце 0 равен нулю.

### Ценность сети

```text
V(N) = k × N²
```

Это учебная оценка потенциальной сетевой ценности, а не бухгалтерская стоимость компании.

### NPV

```text
NPV = Σ Прибыльₜ / (1 + месячная ставка)^t
```

## Как интерпретировать пороги безубыточности

Notebook рассчитывает:

- минимальный ARPU для NPV ≥ 0;
- предельный CAC при текущей пользовательской траектории;
- минимальный темп роста для NPV ≥ 0.

Если предельный CAC выводится как невозможный, это означает, что даже при CAC = 0 проект остаётся убыточным. В таком случае необходимо повышать ARPU, увеличивать рост пользователей или снижать затраты на поддержание.

Каждый порог изменяется отдельно, при сохранении остальных параметров. Поэтому это диагностические ориентиры, а не гарантия результата.
